# rsqrt_unit -- fixed-point reciprocal square root unit (RTL)

Computes `1/sqrt(T)` and returns it in **mantissa + exponent** decomposed form:

```
1/sqrt(T)  =  (v_out / 2^R) * 2^(-sh_out)
```

- `v_out` in `[1/sqrt2, sqrt2] * 2^R` (R fractional bits, 19 bit)
- `sh_out = ceil(e/2)`, where `e` is the position of the MSB of T

---

## 1. Why "mantissa + exponent" instead of a single fixed-point word

`T` spans a very wide range (up to 2^48 in this design), so `1/sqrt(T)` can be
as small as `2^-24`. A single fixed-point representation would need 40+
fractional bits to avoid underflow.

After decomposition:

- the mantissa only needs **R = 18** fractional bits
- the exponent is compensated by a **shift** when the A/B coefficients are
  computed later

This is the key design decision -- **the first version of the Python
simulation used a single fixed-point word and showed a 100% error**, which is
exactly this trap.

---

## 2. Algorithm

```
T = m * 2^e,   m in [1, 2)

1/sqrt(T) = (1/sqrt(m)) * 2^(-e/2)
          = v * 2^(-sh) * (sqrt2, if e is odd)
```

`1/sqrt(m)` is obtained with a lookup table plus linear interpolation:

```
let t = m - 1 in [0, 1)
take the top K bits of t as index j  ->  look up 1/sqrt(1 + j/2^K)
interpolate with the remaining bits  ->  accuracy 13.4 bit
```

---

## 3. Parameters

| Parameter | Default | Description |
|---|---|---|
| `T_W` | 48 | width of T (ample margin while T <= 2^43) |
| `K` | 5 | LUT index width -> **33 entries** |
| `R` | 18 | mantissa fractional bits |
| `FM` | 22 | internal mantissa fractional bits (must be > K) |

**Accuracy**: relative error about 0.009% (13.4 bit); the requirement is 11 bit.

---

## 4. Interface

```verilog
rsqrt_unit #(.T_W(48), .K(5), .R(18), .FM(22)) u_rsqrt (
    .clk       (clk),
    .rst_n     (rst_n),
    .in_valid  (in_valid),
    .t_data    (t_data),      // [T_W-1:0]  T (positive integer)
    .out_valid (out_valid),   // asserted 3 cycles later
    .v_out     (v_out),       // [R:0]  mantissa v
    .sh_out    (sh_out),      // [7:0]  exponent shift sh
    .odd_out   (odd_out)      // parity of e (already folded into v_out, debug only)
);
```

**Pipeline latency = 3 clock cycles.**

---

## 5. Pipeline structure

| Stage | Work | Key signals |
|---|---|---|
| **S1** | leading-one detection (find e) | registers `e_r`, `t_r` |
| **S2** | mantissa extraction + index / fraction / sh / odd | registers `j_r`, `f_r`, `sh_r`, `odd_r` |
| **S3** | table lookup + linear interpolation + sqrt2 correction | outputs `v_out`, `sh_out` |

**Note**: throughput demand is very low (about 288 calls per frame, occupancy
< 2%), so a single unit time-shared across all layers/channels is sufficient
-- **area is prioritised over latency**. If timing is tight, the two
multiplications in S3 can be split into an extra stage.

## 9. Two traps found while implementing (useful for later RTL)

### Trap 1: a "positive" value must be zero-extended before signed arithmetic

`SQRT2_FP = 370728` needs 19 bits, while the signed 19-bit range only reaches
262143 -- treated as signed directly it becomes a **negative** number.

**Fix**: every intermediate that should be positive is zero-extended with
`$signed({2'b00, x})` before entering signed arithmetic.

### Trap 2: the LUT index needs K+1 bits

Interpolation accesses both `lut[j]` and `lut[j+1]`, and `j` can be `2^K - 1`,
so `j+1` can reach `2^K` -- **beyond K bits**.

**Fix**: the LUT `idx` port is **K+1 bits wide**, and the table has `2^K + 1`
entries.

# line_buffer_v2 -- 3x3 window generator with reflection padding

Front end of the convolution core. Consumes a streaming row-scan pixel bus
(P_CI parallel channels) and emits **one 3x3 window per included output
pixel**, with **reflection padding** matching `torch.nn.ReflectionPad2d(1)`
and a **runtime-configurable stride of 1 or 2**.

---

## 1. Interface

```verilog
line_buffer_v2 #(
    .P_CI  (4),      // parallel input channels (1/2/4...)
    .CH_W  (8),      // pixel width (int8)
    .MAX_W (1024),   // max row width
    .ADDR_W(10)      // line RAM address width, MAX_W <= 2**ADDR_W
)(
    .clk, .rst_n,
    .stall,                        // back-pressure: freezes the whole pipeline
    .cfg_w, .cfg_h, .cfg_stride,   // active size + stride (idle-time update)
    .in_valid, .in_ready, .in_px,
    .win_valid, .win_row, .win_col, .win_data
);
```

### Output handshake (important)

`win_valid` is a **LEVEL, not a one-cycle pulse**.  While `stall` is asserted the
current window stays valid on the output so the consumer can still take it with a
normal handshake.  A window is consumed only when

```
win_valid && !stall          <=>   win_valid && fifo_wr_ready
```

A consumer that samples every `win_valid` cycle will count the same window many
times -- this is exactly what made the first version of the stall testbench
report 48/48 failures on a correct design.

`win_data` packs, per channel, the 9 taps of the window **row-major**:

```
tap k = (i+1)*3 + (j+1)     i,j in {-1,0,1}
win_data[(ch*9 + k)*8 +: 8]
=> k=0 top-left ... k=4 centre ... k=8 bottom-right
```

---

## 2. Stride semantics

For stride `S`, padding 1, kernel 3:

```
OUT_W = (W - 1) / S + 1
OUT_H = (H - 1) / S + 1

output pixel (i, j)  <-  window centred at input (S*i, S*j)
                         rows {S*i-1, S*i, S*i+1}
                         cols {S*j-1, S*j, S*j+1}
```

**All input rows and columns are still streamed in and stored.** The windows of
consecutive output rows overlap, so no input can be skipped. The only change is
that a window is *emitted* for a subset of the cycles:

| Condition | Effect |
|---|---|
| `(ph - 2) % S == 0` | emit only stride-aligned columns |
| `(row - 1) % S == 0` | emit only stride-aligned rows |

`cfg_stride` is decoded as `str1 = (cfg_stride != 2)`, so any value other than
2 falls back to stride 1 (identity path). Only 1 and 2 are supported.

### Consequences worth knowing

| Case | Note |
|---|---|
| stride 1, even or odd W | right border reflection is used |
| stride 2, **even** W (e.g. 640) | last output column uses cols `W-3, W-2, W-1` -> **no right border reflection needed** |
| stride 2, **odd** W (e.g. 13) | right border reflection IS used |
| stride 2, even H | the virtual last row is traversed but emits nothing (harmless waste) |

---

## 3. Why only TWO line RAM blocks per channel

Output row `r` needs input rows `r-1, r, r+1`. When input row `k` arrives
(`k = r+1`) the buffers already hold rows `k-2` and `k-1`:

```
block (k%2)     : port0 = WRITE row k     (addr = column)
                  port1 = READ  row k-2   (SAME addr)   <-- read-first
block ((k+1)%2) : port0 = READ  row k-1
```

The same-address read+write on one block relies on the true-dual-port
**READ-FIRST** behaviour: port1 returns the OLD contents (row `k-2`) while
port0 stores the NEW data (row `k`). This is why 2 blocks suffice instead of 3.

Both blocks are instantiated as the `line_ram` module in the same file; swap
it for an Efinity true-dual-port ESRAM primitive at integration time.

---

## 4. Why reflection padding needs no address remapping

Each border reuses a tap that is already available, so the cost is a mux:

| Border | What is needed | How it is obtained |
|---|---|---|
| row `r=0` | row `-1` (virtual) | = current row -> top SR push uses `in_d1` |
| row `r=H-1` | row `H` (virtual) | = row `H-2` -> bottom SR push reuses `rd_top` |
| col `c=0` | col `-1` (virtual) | = col 1 -> left tap reuses the newest column |
| col `c=W-1` | col `W` (virtual) | = col `W-2` -> right tap reuses the oldest column |

The **last output row is produced by a VIRTUAL input row** (`row == cfg_h`)
that consumes no input and only reads. Bandwidth overhead is 2 rows + 2
columns per frame (~0.4%).

The right-border test is stride aware: `at_right = (S*j + 1 >= W)`.

---

## 5. Cycle budget

**`cfg_w + 2` cycles per input row** (`W` input columns + 2 overhead cycles):

| Phase `ph` | Action |
|---|---|
| `0 .. cfg_w-1` | accept input column, write RAM, issue read address (`in_ready = 1` while `row < cfg_h`) |
| `1 .. cfg_w` | RAM data valid -> push shift registers |
| `2 .. cfg_w+1` | emit candidate window for column `(ph-2)/S` when stride-aligned |
| `cfg_w + 1` | closing cycle: `in_ready = 0`, realises the right border |

Throughput = 1 window/cycle while emitting, no bubbles.

## 7. Three traps found while implementing

### Trap 1: two RAM blocks driving the same read net (X on the bus)

The first version drove `rd_top`/`rd_mid` from inside a `generate` loop over
both blocks -- a **multiple-driver conflict**, which ModelSim resolves to `X`.

**Fix**: each block exposes its own read data and an explicit mux selects the
active one (`wr_par`).

### Trap 2: the testbench can be one cycle ahead of the DUT

Driving `in_px` from `feed_next` (i.e. the word for the *next* accepted cycle)
makes the whole stream shift by one pixel, which looks like a padding bug.

**Fix**: present `in_mem[feed]` combinationally and increment `feed` only when
`in_valid && in_ready`.

### Trap 3: the border mux must key off the REGISTERED column

The window data is combinational over the shift registers while `win_col` is a
register. Selecting the border substitution with the combinational column
therefore lags one cycle, and the outer-most SR slot (stale across rows) leaks
into the window.

**Fix**: `at_left` / `at_right` must be derived from `win_col`.

Additionally, for **single-row / single-column images** both border conditions
are true simultaneously; the last-column close must **hold** the newest SR
slot instead of shifting it, otherwise a 1-column image loses its only sample.

# mac_array -- fully parallel 3x3 convolution MAC array

Computes, for one pixel, the dot product of a 3x3 window against the weights
of `P_CO` output channels:

```
out_sum[co] = SUM over (ci, k) of  win[ci][k] * w[co][ci][k]
```

---

## 1. Interface

```verilog
mac_array #(
    .P_CO (8), .P_CI (4), .TAP (9), .CH_W (8), .ACC_W (32), .PIPE (1)
)(
    .clk, .rst_n, .in_valid,
    .win_data,   // [P_CI*TAP*CH_W-1:0]    from line_buffer_v2
    .w_data,     // [P_CO*P_CI*TAP*CH_W-1:0]
    .out_valid, .out_sum   // [P_CO*ACC_W-1:0]
);
```

Data layout (little-endian int8 lanes):

```
win_data[(ci*TAP + k)*CH_W +: CH_W]
w_data  [((co*P_CI + ci)*TAP + k)*CH_W +: CH_W]
out_sum [ co*ACC_W +: ACC_W]                     (signed)
```

---

## 2. Physical size

| Config | MACs / cycle | DSP (dual mode) |
|---|---|---|
| P_CO=8, P_CI=4, TAP=9 | **288** | **144** |
| P_CO=8, P_CI=2 | 144 | 72 |
| P_CO=3, P_CI=4 (out.2 shape) | 108 | 54 |

`P_CI` is the time-multiplexing knob: the surrounding logic feeds `CIN/P_CI`
input-channel groups sequentially and accumulates the partial sums in
`acc_bank`.

---

## 3. Structure

| Stage | Contents |
|---|---|
| 1 | `P_CO * P_CI * TAP` int8 x int8 multipliers (signed, -> ACC_W) |
| 2 | per output channel, a **balanced adder tree** over all `P_CI*TAP` products (ceil-half reduction) |
| 3 | optional output register (`PIPE` = 0 or 1) |

For P_CO=8, P_CI=4, TAP=9 the reduction is `36 -> 18 -> 9 -> 5 -> 3 -> 2 -> 1`
(depth 6, 35 adders per lane, which is the minimum for 36 inputs).

**No overflow** is possible for TAP=9, P_CI<=4: the largest magnitude is
`36 * 128 * 128 = 589,824 < 2^20`, and `ACC_W` is 32.

# acc_bank -- P_PX x P_CO accumulator array with a wide read port

Holds P_PX pixels' worth of P_CO partial sums (32-bit signed) and provides

* a per-pixel **clear**
* a per-pixel **accumulate** (adds the MAC array's P_CO results in one cycle)
* a **wide read** of all P_CO accumulators of one pixel, registered 1 cycle

## 1. Interface

```verilog
acc_bank #(.P_PX(32), .P_CO(8), .ACC_W(32), .PXW(5), .COW(3))(
    .clk, .rst_n,
    .clr_valid, .clr_px,                 // zero one pixel
    .acc_valid, .acc_px, .acc_sum,       // add MAC results into one pixel
    .rd_px, .rd_data                     // wide read, 1 cycle later
);
```

## 2. Why the read port must be WIDE

`postproc` processes P_CO channels per cycle only if it can read all P_CO
accumulators of a pixel at once.  A single-channel read port would serialise
P_CO cycles per pixel; across ~1.9 M pixels that is ~15 M extra cycles on top
of the 8.91 M MAC cycles -- it would nearly **triple** the frame time.  So the
wide port is not a nicety, it is required for the 15 fps target.

## 3. Timing / hazards

| Item | Contract |
|---|---|
| `rd_data` | registered; valid one cycle after `rd_px` |
| read vs write | read returns the value BEFORE any write of the same cycle |
| clear + accumulate | never assert both for the SAME pixel in the SAME cycle |
| read vs accumulate | may target different pixels freely |

|---|---|

# postproc -- merged normalisation + requantisation + ReLU + saturation

## 1. The fusion

```
t = A * acc + B            (instance/batch normalisation)
y = t * M_mul              (requantisation)
        ==>
y = (A * M_mul) * acc + (B * M_mul) = A' * acc + B'
```

One multiplier and one adder per lane.  A' / B' are recomputed once per layer
(416 values for this network).

## 2. Arithmetic (all signed, exact integer semantics)

```
prod = acc * a_mul                    -> PW = ACC_W + A_W bits
sum  = prod + sign_extend(b_add)      -> PW bits
q    = sum >>> SA                     -> arithmetic shift (FLOOR)
q    = (q < 0 && relu_en) ? 0 : q     -> ReLU
y    = min(max(q, SAT_MIN), SAT_MAX)  -> saturation (default +-127)
```

**Rounding**: the shift is a floor, so a round-to-nearest offset must be folded
into `b_add` by the coefficient generator (add `1<<(SA-1)` with the right
sign).  This keeps the datapath free of an extra adder.

**Order**: for ReLU layers the quantisation zero point is non-negative, so ReLU
before saturation does not change the result.  For non-ReLU layers `relu_en=0`
and only saturation applies (verified with relu=0 as well).

|---|---|
| P_RD=8, ACC_W=32, A_W=32, SA=20, relu=1, 133 vectors | PASS |
| same, relu=0 | PASS |

Vectors include saturation extremes (all-max / all-min products) and the

# Milestone M1 -- single-layer end-to-end chain

```
line_buffer_v2  ->  mac_array  ->  acc_bank  ->  postproc
```

## 1. Streaming pipeline (CIN == P_CI)

With one input-channel group and one output-channel group the whole chain is
fully streaming at **one window per cycle**:

| cycle | stage |
|---|---|
| n+0 | line_buffer emits the window for column c |
| n+1 | mac_array outputs the P_CO partial sums (PIPE=1) |
| n+2 | acc_bank has added them into pixel c |
| n+3 | acc_bank wide-read data for pixel c is valid |
| n+4 | postproc outputs the int8 result for column c |

## 2. The accumulator MUST be cleared between output rows

Found the hard way: the accumulator is reused (column index is used as the
pixel index), and without a clear the previous row's value is added on top of
the current row's -- row 0 passes, every later row is wrong.

The contract: **clear once per (pixel, output-channel group), then accumulate
`CIN/P_CI` times.**  In the streaming test the clear is asserted on the emit
cycle, one cycle before the accumulate edge.

## 3. Architectural finding: an elastic window buffer is required when CIN > P_CI

`line_buffer_v2` emits one window per cycle and **cannot be stalled** (its phase
counter free-runs; `in_ready` only means "input taken this cycle").  When
`CIN > P_CI` the MAC array must be time-shared over `CIN/P_CI` groups, i.e. it
needs `CIN/P_CI` cycles per window -- more cycles than windows arrive.

So the chain needs an **elastic window buffer between line_buffer and
mac_array** (a small FIFO), or `line_buffer_v2` must gain a real back-pressure
stall input.  Pick one of these before writing `conv_fsm`.

The multi-group test makes the buffer explicit (drain phase, then replay phase)
to prove the data path is correct.

### Trap 4: a registered RAM read must be FROZEN by stall (the hard one)

`rd_mid` / `rd_top` are **registered** line-RAM read outputs, so their value is
"the word that was read on the previous cycle".

* free-running, the previous cycle's address is exactly `ph-1`, which is what the
  shift-register push expects -- so everything lines up and the design verifies;
* with the read still enabled during a stall, the address stays at `ph` for many
  cycles and the registered output drifts to `mem[ph]`.

The consequence is nasty: the value pushed into the shift registers, and hence the
emitted window, **depends on how long the stall lasted**.  Symptom: exactly the
**centre tap** of the window is wrong (one column too new), only under
back-pressure, and only from a certain point in the layer.

**Fix**: gate the read enable as well.

```verilog
wire rd_en = take_input & ~stall;   // NOT just take_input
```

Freezing `rd_en` makes the read data hold, which is what the push expects.
This was found by comparing two runs of the same testbench (with and without
stall) and diffing the internal state cycle by cycle -- the shift-register
contents were identical while `win_data` differed, which pointed straight at the
combinational mux over `rd_mid`.

# win_fifo -- elastic window buffer

A small first-word-fall-through FIFO that decouples the free-running line
buffer from the slower MAC-side consumer.

## 1. Why a small FIFO is the right answer (and why a big one is not)

| Side | Rate |
|---|---|
| line_buffer | 1 window per cycle |
| MAC (CIN > P_CI) | 1 window per `CING*COG` cycles |

The gap is `CING*COG` (up to 32 for this network), so a purely buffering solution
would have to hold a **layer-sized** backlog: enc.1 alone would need ~154k windows
(~5 MB) and `dec.3` ~232k.  That does not fit on chip.

So the FIFO is deliberately **small (16 entries)**: it only hides the
back-pressure round-trip latency and absorbs burstiness.  The actual rate
matching is done by driving `stall` on the line buffers from `~wr_ready`.

## 2. Interface

```verilog
win_fifo #(.DW(592), .DEPTH(16), .AW(4))(
    .clk, .rst_n,
    .wr_valid, .wr_ready, .wr_data,
    .rd_valid, .rd_ready, .rd_data,     // first-word fall-through
    .full, .empty, .level
);
```

`rd_data` always shows the head and `rd_valid` is high while non-empty, so the
consumer pops with `rd_valid && rd_ready`.

Mapping note: the combinational head read suits a small distributed-RAM /
register implementation.  For an ESRAM with a registered read, `rd_valid` must be
delayed one cycle to match.

## 3. Verification: PASS

| Case | Result |
|---|---|
| DW=16, DEPTH=8, 200 items, random write gaps + a forced full period | PASS |
| DW=592, DEPTH=16, 300 items (real entry width) | PASS |

Checks: pop order equals push order (no loss, no duplication), `level` never
exceeds `DEPTH`, FIFO empty out of reset, and the fill/back-pressure path is
provably exercised (`filled_once`).

## 1. Timing traps found here

1. **`mac_valid` / `mac_win` / `mac_w` must be COMBINATIONAL.**  Registered, they
   stayed low for the first cycle of `S_MAC` and silently dropped input-channel
   group 0.
2. **The accumulator clear must be issued on the FIRST `S_MAC` cycle.**  `acc_px`
   is registered, so a clear asserted in `S_IDLE` samples the *previous* pixel
   index and wipes the wrong accumulator.
3. **The registered wide read needs a settle cycle** after the last accumulate,
   otherwise the read returns the pre-commit value.

# weight_mgr -- double-buffered weight fetch engine

Fetches one (cog, cig) weight group (P_CO x P_CI x TAP bytes) from the external
weight store into an on-core register buffer, so the MAC array can read all 288
weights combinationally for a whole pixel tile.

## 1. Load cost -- the thing the first analysis missed

The original throughput analysis only checked that 9 B/cycle of weight bandwidth
was "available"; it never **charged** the load time against the frame budget.
Charging it changes the answer:

| T | weight read port | total cycles | ms | frame budget | load overhead |
|---|---|---|---|---|---|
| 32 | 1 block (8 B/cy) | 18.41 M | **73.7** | **110%** | 52% |
| 32 | 2 blocks | 13.66 M | 54.6 | 82% | 35% |
| **32** | **4 blocks (32 B/cy)** | **11.28 M** | **45.1** | **68%** | 21% |
| 32 | 8 blocks | 10.10 M | 40.4 | 61% | 12% |
| 64 | 4 blocks | 10.10 M | 40.4 | 61% | 12% |
| 128 | 4 blocks | 9.50 M | 38.0 | 57% | 6% |

The ratio is `(288 / read_bandwidth) / T`, and it is **independent of P_co /
P_ci** (they appear in both numerator and denominator).  The only structural
knobs are the tile size T and the read-port width.

Chosen: **T = 32 with a 4-block (32 B/cycle) read port**, which gives a 9-cycle
load that fits inside a 32-cycle tile -- i.e. it can be **hidden completely by
double buffering**, bringing the layer back to the pure compute rate
(8.91 M cycles ~= 35.6 ms).

## 2. Interface

```verilog
weight_mgr #(.P_CO(8), .P_CI(4), .TAP(9), .CH_W(8), .RD_B(32))(
    .clk, .rst_n,
    .mem_addr, .mem_rdata,          // external store, registered read
    .ld_req, .ld_base, .ld_sel,     // load into buffer 0 or 1
    .ld_busy, .ld_done,
    .sel_buf, .w_data               // NW*8 bits presented combinationally
);
```

## 3. Trap: the address must lead the row being written

`mem_addr` is a non-blocking assignment, so it changes only after the posedge.
The first version set `mem_addr = ld_base` and then incremented it inside the
load state -- which meant the posedge that should have sampled row 1's address
still sampled row 0, so **every row after the first fetched row 0 again**
(symptom: entry 0..31 correct, everything after that a copy of entry 0).

Fix: keep an explicit base register and drive the address **one row ahead** of
the row being written:

```verilog
S_ADDR: mem_addr <= base_r + RD_B;              // row 0's data next cycle
S_LD  : mem_addr <= base_r + (cnt + 2) * RD_B;  // always one row ahead
```

Total latency is `2 + NCY` cycles (11 for NW=288, RD_B=32).

## 4. Verification: PASS

3 loads across both buffers, checking every one of the 288 bytes each time, that
loading B does not disturb A, and that `ld_done` arrives at exactly `2 + NCY`.

# win_cache -- tile window cache (sequential write, random read)

Holds one tile of windows: DEPTH pixels, each carrying CING input-channel
groups.

## 1. Why a FIFO is not enough

| side | access pattern |
|---|---|
| write (line buffers) | pixel0{group0..groupN}, pixel1{...} -- sequential |
| read (compute) | output-group -> input-group -> pixel -- **strided by CING** |

The compute order needs, for one fixed input group, all pixels of the tile,
which are `CING` apart in the write stream.  A FIFO can only be read in write
order, so the storage must accept a **random read address**.  (`win_fifo`, built
earlier for the M1 chain, is the right part for rate decoupling but the wrong
part here; `win_cache` supersedes it in the C group.)

## 2. Organisation and back-pressure

DEPTH entries of CING*DW bits.  Written as a whole bundle in one cycle, read back
as a whole bundle, then a variable part-select picks the group the MAC needs:

```verilog
assign rd_group = bundle_r[cig_sel*DW +: DW];
```

`wr_ready` goes low when full so the caller can freeze the line buffers (same
contract as `win_fifo`).  A `flush` input resets the write pointer between tiles.

## 3. Trap: derive the address/selector widths, do not hardcode them

The first testbench hardcoded `GW = 1`.  With CING = 4 or 8 that silently
selected group 0 only, so the check failed for every group above 1.  The RTL was
correct; the **test** was wrong.  Use `$clog2` of the parameter.

## 4. Verification: PASS

| Case | Result |
|---|---|
| CING=1, DEPTH=8 | PASS |
| CING=2, DEPTH=8 | PASS |
| CING=4, DEPTH=8 | PASS |
| CING=8, DEPTH=4 | PASS |

Checks the compute-order read-back of every group of every pixel, that an
over-fill is rejected, and the full/empty flags.

# conv_fsm -- single-layer sequencer

## 1. The loop structure

```
for tile in tiles(NPIX, T)
  for cog in COG                    COUT / P_CO
    CLEAR the tile's accumulators
    for cig in CING                 CIN / P_CI
      LOAD weight group (cog, cig)
      MAC over the whole tile
    EMIT the tile
```

**Why cig is inside cog and the MAC runs over the whole tile**: the weight group
stays in the buffer for the entire tile, so weights never change while a tile is
computed.  That is what makes the wide weight port affordable -- and it is also
exactly why the window cache must support random reads.

**Why EMIT is once per output group, not per input group**: getting this wrong
was a real bug.  Emitting inside the cig loop made a CING=2 layer emit twice as
many pixels as it has.

## 2. Traps found while integrating

### 2.1 The line buffers must be frozen until the configuration is valid

A line buffer free-runs out of reset.  Before `S_INIT` has run, `cfg_w` and
`cfg_h` are still 0, so its phase and row counters advance with meaningless
parameters and it enters the real fill in an arbitrary state.

**Fix**: stall the line buffers whenever the FSM is not filling:

```verilog
assign lb_stall = (st != S_FILL) | ~wc_wr_ready;
```

### 2.2 Gate the cache write on lb_win_valid

`win_valid` has gaps -- the line buffer is idle on its row-overhead cycles.
Writing on those cycles stores garbage and **desynchronises the write count from
the pixel index** (symptom: the cache filled to 32 while only 16 windows had been
written).

```verilog
assign wc_wr_valid = (st == S_FILL) && lb_win_valid;
```

### 2.3 Registered reads must be pre-issued

`acc_bank`'s wide read is registered, so `rd_px` must lead `pp_valid` by one
cycle.  Issuing both in the same cycle produced an output stream shifted by one
pixel.

```verilog
S_PX  end: rd_px <= 0;                 // pre-read emit pixel 0
S_EMIT   : pp_valid <= 1; rd_px <= px_i + 1;   // pre-read the next pixel
```

## 3. Verification: PASS (layer self-sequenced)

| Case | Result |
|---|---|
| CING=1, CIN=3, COUT=8, H=6, W=8, T=32, NTILE=2 | PASS (48/48 bit-exact) |
| CING=2, CIN=8, COUT=8, H=6, W=8, T=32 | PASS (48/48 bit-exact) |

The testbench supplies only the input pixel stream and the golden vectors; every
control signal comes from `conv_fsm`.

# B group -- normalisation statistics and coefficients

With the B group the convolution core stops being a plain filter: it can compute
its own InstanceNorm parameters.  Before this the A'/B' constants were supplied
by the testbench.

```
           wide acc read (during EMIT)
                    |
                    v
              acc_reduce  --> S1, S2  (per channel, whole layer)
                                |
                                v
                          norm_coeff  --> A', B'   (uses rsqrt_unit)
                                |
                                v
                          coeff_table  --> postproc
```

The whole chain is **frame-reuse** friendly: layer L's statistics are gathered
while its data streams through, the coefficients are ready at the end of the
frame, and the next frame's pass reads them back from `coeff_table`.  No layer
ever needs a second pass over its own data.

# acc_reduce -- S1 / S2 statistics accumulator

## 1. What it computes

```
S1[co] = SUM_pixels (acc >> SH)
S2[co] = SUM_pixels (acc >> SH)^2
```

from which `T = N*S2 - S1^2` ( == N^2 * variance, exact in integers ).

It taps the **same wide accumulator read** that postproc uses during EMIT, so
gathering statistics costs no extra memory traffic at all.

## 2. Clear semantics

CLEAR once per **LAYER**, not per tile: a channel's statistics span every tile,
so the accumulators persist across tiles and only reset when the next layer
starts.

## 3. Two traps, both about Verilog signedness

### Trap 3.1: `+` binds tighter than `>>>`

```verilog
s1[c] <= s1[c] + $signed(x) >>> SH;      // WRONG: shifts the whole sum
s1[c] <= s1[c] + ($signed(x) >>> SH);    // right
```

### Trap 3.2: the squaring multiply must happen in a SIGNED context

`s2` is an **unsigned** reg, so writing

```verilog
s2[c] <= s2[c] + ($signed(x) >>> SH) * ($signed(x) >>> SH);
```

makes the whole right-hand side unsigned: the `$signed()` casts are discarded
and a negative sample is squared as its raw 32-bit pattern (e.g. `-936` becomes
`4294966360`).  The accumulator wrapped to ~2^56.

**Fix** -- declare the product wire `signed`, then the multiply stays signed and
the (always non-negative) result can be zero-extended into the unsigned
accumulator:

```verilog
wire signed [ACC_W-1:0]   x_sh [0:P_CO-1];
wire signed [2*ACC_W-1:0] x_sq [0:P_CO-1];
assign x_sh[g] = $signed(acc_in[g*ACC_W +: ACC_W]) >>> SH;
assign x_sq[g] = x_sh[g] * x_sh[g];
...
s2[c] <= s2[c] + x_sq[c][S2_W-1:0];
```

## 4. Verification: PASS

400 scripted accumulate/clear operations; every S1/S2 pair matches the
reference bit-exactly.

# norm_coeff -- S1, S2 -> A', B'

## 1. The derivation (all integers)

```
x     = acc >> SH                                  (per pixel, in acc_reduce)
T     = N*S2 - S1^2                                == N^2 * variance, exact
rsqrt = 1/sqrt(T) = (v / 2^R) * 2^(-sh)            (mantissa + exponent)

A  = gamma/sigma = gamma*N/sqrt(T)  = (gamma*N*v) >> (R+sh)
B  = beta - mu*A  = beta - (gamma*S1*v) >> (R+sh)
```

The requantisation scale folds in as a single scaled input, so postproc still
needs only ONE multiply-add per lane:

```
GAMMA_FP = round(gamma_eff * 2^SA)      beta_eff already includes M_mul
BETA_FP  = round(beta_eff  * 2^SA)

A' = (GAMMA_FP * N  * v) >> (R+sh)
B' =  BETA_FP           - ((GAMMA_FP * S1 * v) >> (R+sh))
```

**Why the shift is dynamic**: T spans 2^0 .. 2^48, so 1/sqrt(T) spans
2^0 .. 2^-24.  A fixed-point reciprocal would underflow; mantissa+exponent makes
the shift a runtime value (a barrel shifter in hardware).

`T` is clamped to `T_MIN` so a perfectly flat channel cannot divide by zero.

## 2. Trap 3.3: the same unsigned-context trap, again

`gn_prod` / `gs1_prod` were declared `wire [PW-1:0]` (unsigned).  With
`gs1 = GAMMA_FP*S1` negative, the unsigned context reinterpreted it as a huge
positive value and `>>>` degraded to a **logical** shift, so B' saturated to the
most negative value while A' (whose operands are positive) stayed correct.

**Fix**: declare them `signed`.  Two occurrences of this trap in one afternoon --
worth remembering.

## 3. Latency

`1 (compute T and launch rsqrt) + 3 (rsqrt pipeline) + 1 (final multiply/shift)
= 5 cycles` per channel.

## 4. Verification: PASS

205 vectors, including the `T_MIN` degenerate case and large-T cases, all
bit-exact.  Vectors include negative `S1` so the B offset path is exercised.

# coeff_table -- A'/B' store

Holds DEPTH entries (one per layer, or per (layer, output-channel group)), each
carrying two vectors of P_CO words.

* **writes are per channel** -- that is the rate `norm_coeff` produces them
* **reads are whole-vector** -- that is the rate `postproc` consumes them
* both ports are registered, like acc_bank's wide read

This is what makes frame-reuse possible: the coefficients written at the end of
frame N are read back during frame N+1.

## Verification: PASS

Every entry and every channel checked after a full write pass, including that
writing one entry does not disturb another.

# M2 milestone -- one layer WITH InstanceNorm, end to end

```
line_buffer x CING -> win_cache -> mac_array -> acc_bank -> postproc
                                        |            |
                                        |            +-- acc_reduce (S1/S2)
                                        |                     |
                                        |                 norm_coeff
                                        |                     |
                                        +----------- coeff_table
```

## 1. How the layer is exercised

`conv_fsm` drives everything; the testbench only supplies pixels and golden
vectors.  The layer is run **twice**:

| phase | what happens |
|---|---|
| PASS 1 | stream the layer; `postproc` output ignored, `acc_reduce` gathers S1/S2 |
| COEFF  | `norm_coeff` converts each channel's S1/S2 into A'/B' (via `rsqrt_unit`) and stores them in `coeff_table` |
| PASS 2 | stream the same layer again, now with `postproc` reading the coefficients |

A real system does not do two passes -- it uses frame N's statistics to
normalise frame N+1, so the coefficients are simply read back.  Running the same
input twice reproduces that exact data flow (same statistics, same coefficients)
without needing a second frame.

The postproc input is `acc >> SH`, matching the definition of the statistics:
A' is defined against `x_s = acc >> SH`, so the same shift must be applied on the
way in.

## 2. Trap 3.4: `%d` in Verilog pads with SPACES

```verilog
$sformat(fn, "%s/m2_in_g%d.mem", `VDIR, kk);   // -> "m2_in_g          0.mem"
$sformat(fn, "%s/m2_in_g%0d.mem", `VDIR, kk);  // right
```

Unlike C, Verilog's `%d` pads the field with spaces to the width of the
expression, so every `$readmemh` silently failed to open its file and the whole
design came up as X.  **Always use `%0d` in filename formatting.**

## 3. Trap 3.5: the same unsigned-context trap in the integration glue

```verilog
wire [PCO*ACCW-1:0] acc_s;
assign acc_s[g*ACCW +: ACCW] = $signed(acc) >>> SH;   // WRONG: logical shift
```

Fix: keep a signed per-channel wire and copy the bits.

## 4. Verification: PASS

| Case | Result |
|---|---|
| CING=1, CIN=3, COUT=8, H=6, W=8, SH=4, SA=24 | PASS (statistics + coefficients + 384 outputs bit-exact) |
| CING=2, CIN=8, COUT=8 (deployment shape) | PASS (same) |

Both cases produce 167-177 non-zero outputs out of 384 with zero saturation, so
the test is not vacuous.
